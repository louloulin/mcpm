# MCP 服务器更新通知系统

## 概述

MCP 服务器更新通知系统是一个自动化系统，用于监控服务器依赖关系，并在依赖的服务器发布新版本时通知用户。这确保了用户总是了解可用的最新版本，从而保持他们的 MCP 服务器生态系统处于最新状态和安全状态。

## 主要功能

- **自动依赖监控**: 系统定期检查所有注册服务器的依赖项
- **版本比较**: 使用语义化版本规则（SemVer）比较当前版本和最新版本
- **用户通知**: 当发现新版本时，通过站内消息通知相关用户
- **实时更新**: 通知显示在用户界面的通知中心，包含更新详情和版本信息

## 工作原理

更新通知系统通过以下步骤工作：

1. **定期检查**: 系统每 12 小时自动检查一次所有服务器的依赖
2. **版本分析**: 对每个依赖项进行语义化版本比较，识别新版本
3. **用户匹配**: 确定哪些用户安装了需要更新的服务器
4. **通知生成**: 为相关用户创建通知，包含依赖更新的详细信息
5. **通知派发**: 将通知发送到用户的通知中心

## 数据库结构

系统使用以下表来跟踪依赖关系和管理通知：

- `dependencies`: 存储服务器之间的依赖关系
- `userServers`: 跟踪用户安装的服务器
- `notifications`: 存储用户通知

## 界面集成

更新通知系统完全集成到 MCP 服务器仓库的 Web 界面中：

- 通知中心可通过顶部导航栏中的铃铛图标访问
- 未读通知数量显示在图标上的徽章中
- 通知可以单独标记为已读或一次性全部标记为已读
- 更新通知包含指向更新详情的链接

## 用例示例

假设用户安装了服务器 A（版本 1.0.0），而服务器 A 依赖于服务器 B（版本 2.0.0）。如果服务器 B 发布了新版本 2.1.0，更新通知系统会：

1. 检测到服务器 B 的新版本
2. 识别服务器 A 依赖于服务器 B 的较旧版本
3. 找出安装了服务器 A 的所有用户
4. 向这些用户发送通知，告知他们服务器 B 有新版本可用
5. 提醒用户更新依赖以获取最新功能和安全修复

## 开发者指南

### 如何为您的服务器添加依赖

在您的服务器定义中，使用 `dependencies` 字段指定依赖项：

```json
{
  "name": "your-server",
  "version": "1.0.0",
  "dependencies": {
    "other-server": "^2.0.0",
    "utility-server": "~1.5.0"
  }
}
```

系统将自动跟踪这些依赖项并在有新版本时通知用户。

## 管理员指南

更新通知系统可以通过环境变量进行配置：

- `UPDATE_CHECK_INTERVAL`: 更新检查间隔（小时），默认为 12
- `NOTIFICATION_EXPIRY`: 通知过期时间（天），默认为 30

## 结论

MCP 服务器更新通知系统通过确保用户了解依赖更新，显著提高了生态系统的安全性和用户体验。这种主动方法使用户能够及时更新他们的依赖，从而减少了由过时软件引起的潜在问题。
