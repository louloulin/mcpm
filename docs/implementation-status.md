## Webhooks 功能

Webhooks 功能已全部完成，包括：

1. **数据模型**
   - Webhook 配置模型
   - 事件记录模型
   - 安全签名机制

2. **API 端点**
   - 创建 Webhook：POST /api/webhooks
   - 获取 Webhook 列表：GET /api/webhooks
   - 获取单个 Webhook：GET /api/webhooks/:id
   - 更新 Webhook：PATCH /api/webhooks/:id
   - 删除 Webhook：DELETE /api/webhooks/:id
   - 触发 Webhook 事件：POST /api/webhooks/trigger

3. **安全特性**
   - HMAC 签名验证
   - 事件负载加密
   - 请求超时设置

4. **可靠性措施**

5. **单元测试**

## 文件存储系统

**完成日期**: 2023年8月

**功能描述**: 
文件存储系统提供统一的接口来管理和存储各种类型的文件，支持多种存储后端。

**实现细节**:

1. **多存储后端支持**:
   - 本地文件系统适配器 (完成)
   - Amazon S3适配器 (完成)
   - Azure Blob Storage适配器 (完成)
   - Google Cloud Storage适配器 (完成)

2. **核心组件**:
   - FileStorageService接口
   - FileStorageFactory工厂类
   - 各种存储适配器实现
   - 文件元数据管理
   - 访问控制实现
   - 临时URL生成

3. **API端点**:
   - 文件上传
   - 文件下载
   - 元数据管理
   - 文件查询
   - 批量操作

**特性**:
- 统一的API接口，便于更换后端存储
- 支持多种访问权限：公开、私有、受保护
- 支持通过实体关联组织文件（如用户头像、服务器配置等）
- 支持元数据存储和检索
- 支持基于多种条件的文件查询和过滤
- 支持生成带有过期时间的安全下载链接
- 支持所有主流云存储服务（AWS S3、Azure Blob、Google Cloud Storage）

**文档**:
- [文件存储设计文档](./file-storage.md)
- [API参考](./api-reference.md#file-storage)

   - `FileProcessingService` - 主要处理服务

## 更新通知系统

**完成时间**: 2025年3月

**功能描述**: 更新通知系统自动监控服务器依赖关系，在依赖服务器发布新版本时通知相关用户，确保用户及时了解可用更新。

**实现细节**:

1. **核心组件**:
   - UpdateNotifier服务类 (完成)
   - 依赖版本比较算法 (完成)
   - 用户通知生成器 (完成)
   - 定时检查调度器 (完成)

2. **数据库结构**:
   - 依赖关系表 (dependencies)
   - 用户服务器关联表 (userServers)
   - 通知表 (notifications)

3. **API端点**:
   - 获取通知列表
   - 标记通知为已读
   - 标记所有通知为已读

4. **UI组件**:
   - 通知中心
   - 通知徽章
   - 通知详情视图
   - 更新操作按钮

**特性**:
- 基于语义化版本(SemVer)的智能版本比较
- 自动定期检查依赖更新（默认12小时）
- 针对性用户通知，只通知受影响用户
- 完整的通知管理UI
- 与现有通知系统无缝集成
